# GameVault

A cloud-based gaming platform for discovering, managing, and getting personalized recommendations for video games. GameVault combines a Flask web application with a content-based machine learning recommender, OAuth authentication, and a multi-database architecture, all deployed on Google Cloud Run.

**Live application:** [gamevault.jakupi.net](https://gamevault.jakupi.net) (also accessible at [gaming-web-app-811585373744.europe-west1.run.app](https://gaming-web-app-811585373744.europe-west1.run.app))

## Overview

GameVault is a full-stack gaming webstore that lets users browse a curated catalog of 35 modern titles, build a personal library, and receive recommendations generated by a content-based unsupervised machine learning model. The application is built around a polyglot persistence model: a managed MySQL instance on Railway handles relational data (users, sessions, library ownership), while MongoDB Atlas stores rich game metadata sourced from the RAWG Video Games Database API. The system is containerized with Docker and deployed as a serverless service on Google Cloud Run.

## Features

- **OAuth & local authentication** — Sign in with Google or Steam via Authlib, or use a traditional email/password account secured with bcrypt hashing.
- **Curated game catalog** — 35 titles spanning multiple genres, platforms, price points, and availability states, enriched with metadata, tags, and imagery from the RAWG API.
- **Filterable search** — A search bar with filters lets users narrow the catalog by genre, platform, price, and availability.
- **Personal library** — Users can add or remove games from their library, with ownership tracked in MySQL and synchronized across services.
- **Machine learning recommendations** — A content-based unsupervised model built with scikit-learn computes a precomputed similarity matrix from game tags and user activity, producing personalized suggestions based on the games already in a user's library.
- **REST API** — JSON endpoints expose the catalog, search, library, and recommendation features for external clients.
- **Cloud-native deployment** — Containerized with Docker, served by Gunicorn, and hosted on Google Cloud Run with a custom domain.
- **Automated maintenance** — Cloud functions handle recommendation generation and library synchronization in the background.

## Architecture

GameVault uses a polyglot persistence design that pairs relational and document stores with a precomputed ML artifact:

- **Railway MySQL** stores users, sessions, and library relationships, providing strong referential integrity for transactional data.
- **MongoDB Atlas** stores game metadata as flexible documents, making it easy to evolve the schema as new fields and tags are pulled from the RAWG API.
- **scikit-learn similarity matrix** is trained offline by `train_model.py` and serialized to `similarity_matrix.pkl` and `games_metadata.pkl`, allowing the live application to serve recommendations with a fast lookup rather than a per-request inference call.
- **Google Cloud Run** runs the containerized Flask app behind Gunicorn, scaling automatically with traffic.

## Technology Stack

**Backend:** Flask, Python 3.12, Gunicorn, SQLAlchemy, MongoEngine

**Authentication:** Flask-Login, Flask-Bcrypt, Authlib (Google & Steam OAuth), python-openid

**Databases:** MySQL on Railway (relational), MongoDB Atlas (document store)

**Machine Learning:** scikit-learn, pandas, content-based unsupervised similarity

**External APIs:** RAWG Video Games Database API

**Infrastructure:** Docker, Google Cloud Run, custom DNS via gamevault.jakupi.net

**Testing:** Pytest

## Installation

Clone the repository and install dependencies into a virtual environment:

```bash
git clone <repository-url>
cd GameVault
python -m venv venv
source venv/bin/activate          # On Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Configuration

Create a `.env` file in the project root with the following variables:

```
# Flask
SECRET_KEY=your_flask_secret_key

# Railway MySQL
DATABASE_URL=mysql+pymysql://user:password@host:port/database

# MongoDB Atlas
MONGO_URI=your_mongodb_connection_string

# RAWG API
RAWG_API_KEY=your_rawg_api_key

# Google OAuth
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret

# Steam OAuth
STEAM_API_KEY=your_steam_api_key
```

Initialize the MySQL schema by running `database/schema.sql` against your Railway database. If you are upgrading from an older version, also run `database/insert_column.sql`.

If you need to populate or rebuild the recommendation artifacts, run:

```bash
python enrich_game_metadata.py    # Pull metadata from RAWG into MongoDB
python train_model.py             # Train and serialize the similarity matrix
```

## Running the Application

For local development:

```bash
python main.py
```

For a production-like environment using Gunicorn:

```bash
gunicorn -c gunicorn.conf.py main:app
```

The app will be available at `http://localhost:8080` by default.

## Deployment

GameVault is deployed to Google Cloud Run as a containerized service. To build and deploy:

```bash
# Build the container image
docker build -t gamevault .

# Submit to Google Cloud Build and deploy to Cloud Run
gcloud builds submit --tag gcr.io/<project-id>/gamevault
gcloud run deploy gamevault \
    --image gcr.io/<project-id>/gamevault \
    --region europe-west1 \
    --platform managed \
    --allow-unauthenticated
```

Environment variables should be set on the Cloud Run service (either through the console or via `--set-env-vars`). The custom domain `gamevault.jakupi.net` is mapped to the Cloud Run service through Cloud Run's domain mapping feature.

## API Reference

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/games` | Retrieve all games in the catalog |
| `GET` | `/api/games/<id>` | Retrieve metadata for a single game |
| `GET` | `/api/games/search?q=<query>` | Search the catalog with optional filters |
| `GET` | `/api/library/<user_id>` | Retrieve a user's game library |
| `GET` | `/api/recommendations/<user_id>` | Retrieve personalized recommendations |

All endpoints return JSON. Authenticated endpoints require a valid session cookie.

## Database Schema

**MySQL (Railway)**

- `users` — User accounts and credentials (bcrypt hashes for local accounts, OAuth identifiers for federated logins)
- `user_sessions` — Active session records
- `user_library` — Many-to-many relationship between users and owned games
- `games` — Minimal game records maintained for referential integrity with the library table

**MongoDB Atlas**

- `games` — Full game metadata: title, description, genres, tags, platforms, price, availability, images, and ratings
- `user_activity` — User interaction events used as input to the recommendation model
